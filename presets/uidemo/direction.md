# 제품 화면 시연 — 연출 프롬프트

잘 만든 SaaS 런칭 영상처럼, 우리 앱 화면 안에서 커서가 움직이고 누르고 타자 치며 카메라가 필요한 곳으로 다가가는 영상이에요.
실제 앱 스크린샷은 쓰지 않아요. 단순하게 그린 가짜 화면을 브랜드 색으로 칠해서, 어떤 브랜드든 "우리 앱이 이렇게 일해요"를 보여 줄 수 있어요.
앱·웹 서비스 새 기능, AI 기능 소개, 업데이트 안내, 주문 앱·예약 서비스 홍보에 잘 맞아요. 문구는 다른 결 템플릿과 같은 content 를 그대로 읽어요.

## 형식
- 템플릿: `uidemo` (제품 화면 시연) · 기본 스타일 `agent-cursor-board` (연출 탭에서 바꿀 수 있어요)
- 비율: 9:16 · 4:5 · 1:1 · 16:9. 사건은 0.25초 격자, 큰 사건은 0.5초 단위
- 길이는 항목 수로 정해져요. 예시(항목 3개, 숫자 있음, 사진 없음) 17.5초, 사진 2장을 넣으면 20.5초, 항목 5개·사진 4장이면 23초 안팎
  - 훅: 다 쳐진 뒤 0.9초 읽고 보내기 (최소 2초)
  - points: 보내기 뒤 약 1.3초 + 항목마다 1.3초 (뼈대 줄 → AI 커서 0.3초씩 → 체크 1초씩)
  - number: 약 3.5초 / photos: 약 3초 + 장당 0.1초 / cta: 버튼이 있으면 약 6초, 없으면 약 4초
  - points·number·photos 는 비우면 그 장면이 통째로 빠지고, 보내기를 누르면 바로 다음 화면으로 넘어가요. 다 비우면 9.5초쯤

## 보는 느낌
- 16:9 는 화면 80%쯤 되는 데스크톱 앱 창(위 막대에 점 셋과 탭, 왼쪽 메뉴에 아이콘과 이름 막대), 1:1 은 화면을 거의 채운 앱 창(옆 메뉴는 아이콘만).
- 9:16·4:5 는 아래가 화면 밖으로 잘린 큰 폰. 머리줄(로고 칸 + 오른쪽 알약 메뉴)부터 내용까지 모두 세이프존 안에 있고,
  9:16 의 세이프존 아래에는 타자 칠 때 키보드가 올라왔다 내려가고, 그 뒤엔 빈 입력 막대가 장식으로 남아요.
- 바탕은 브랜드 바탕색에 아주 옅은 점 격자. 앱 화면은 종이색(paper)과 글자색(ink) 짝이라 밝은 브랜드·어두운 브랜드 모두 읽혀요.
- 이 영상의 주인공 소품은 **커서**예요. 사람 커서(검정 화살표, 버튼 위에선 손가락)가 누르고, 결과를 만들 때만 강조색 AI 커서(반짝이와 점 세 개 꼬리표)가 지나가요.
- 큰 글자 슬램·손그림·그라디언트 구슬·콜라주는 쓰지 않아요. 글은 UI 크기 위주이고, 훅과 마지막 한 줄만 크게.

## 장면
1. 훅 (0–2.5초): 앱 창이 살짝 떠오르며 카메라가 0.9배쯤에서 1배로 다가가요. kicker 는 창 위 탭으로 톡(폰·브라우저 틀은 입력창 위 배지).
   커서가 가운데 큰 입력창을 누르면 테두리가 강조색으로 켜지고(9:16 은 키보드가 올라옴), title 이 타자로 쳐져요. highlight 낱말은 강조색 띠.
   16:9·1:1 은 타자 치는 동안 카메라가 입력창으로 조금 다가가요. 다 쳐지면 커서가 보내기 버튼으로 가서 눌러요.
2. points: 보낸 글이 말풍선처럼 작아져 오른쪽 위로 올라가고, 그 아래 항목 수만큼 뼈대 줄이 반짝이며 생겨요.
   AI 커서가 오른쪽에서 들어와 줄을 하나씩 지나가면, 지나간 줄이 강조색으로 잠깐 덮였다가 진짜 글(point)로 바뀌어요.
   이어 사람 커서가 항목마다 체크 칸을 눌러 체크가 그어지고 줄이 강조색으로 물들어요. 그때마다 카메라가 그 줄 쪽으로 살짝(1.08~1.16배) 다가가요.
3. number: 커서가 메뉴의 그래프 아이콘을 누르면 선택 표시가 미끄러지고 화면이 옆으로 밀려 대시보드가 들어와요.
   큰 KPI 카드 안에 label(작은 글) → 숫자(prefix·value·suffix)가 올라가고, 선 그래프가 왼쪽부터 그려진 뒤 끝점이 숨 쉬어요. source 는 카드 아래 작은 글.
   옆이나 아래의 작은 카드 둘은 막대가 올라오는 장식이에요(숫자 없음). 카메라는 KPI 카드 쪽으로 다가가요.
4. photos: 갤러리 아이콘을 누르면 사진이 가운데에 기울어진 채 한 무더기로 쌓였다가, 칸으로 펼쳐져요(1장 꽉, 2장 나란히, 3장 큰 1 + 작은 2, 4장 2×2).
   커서가 첫 사진을 고르면 강조색 테두리가 생기고 카메라가 다가가요. 사진은 천천히 확대돼요.
5. cta: 깃발 아이콘을 누르면 마지막 화면. headline 이 줄마다 올라오고 큰 버튼(cta.button)이 톡 튀어나와요.
   카메라가 버튼으로 다가가고 커서가 누르면, 버튼에 체크가 붙고 위에서 토스트(체크 + sub, sub 가 없으면 로고 글자)가 내려와요.
   카메라가 0.9배쯤으로 빠지며 로고 칸·로고 글자 → sub → note 가 차례로 들어와요. 버튼이 없으면 누르기와 토스트 없이 바로 빠지며 로고가 들어와요.

## 움직임
- 등장은 고른 스타일의 이징(`S.ease`), 간격은 `S.stg` 를 따라요. 버튼·체크·메뉴 선택 표시는 넘침이 아주 적은 스프링.
- 카메라는 0.6~0.9초 inOut 으로만 움직이고, 다가갈 때도 내용 영역 전체가 세이프존 안에 남는 범위에서만 끌어당겨요. 초점 대상은 언제나 세이프존 안.
- 커서는 곧은 선 대신 살짝 휜 길로 0.45~0.55초에 옮겨 가고, 누를 때 살짝 작아지며 물결 원이 퍼져요. 버튼 위에서는 손가락 모양.
- 화면 바꾸기는 앱 안에서만: 옆으로 7u 밀려 들어오고 앞 화면은 반대로 빠져요. 화면을 통째로 자르거나 겹치는 전환은 쓰지 않아요.
- 바운스·파티클은 쓰지 않아요. 계속 움직이는 것은 뼈대 반짝이, AI 꼬리표 점 세 개, 그래프 끝점의 숨, 사진의 느린 확대뿐이에요.

## 스타일을 고르면
- `scenes.title` 이 있으면 title·headline 이 그 방식으로 들어와요(없으면 title 은 타자, headline 은 줄마다 올라옴). `scenes.number` 는 숫자 방식.
- `scenes.bg`: dots(기본)·grid·lines 는 바탕 무늬, aurora·mesh 는 가장자리에 떠도는 빛 안개, solid·none 은 민바탕.
- `scenes.card`: outline 이면 창이 얇은 선으로, flat·paper 면 그림자 없이. `scenes.marker`: highlight(띠)·underline·color 로 강조 낱말 모양이 바뀌어요.
- `scenes.weight`·`tracking`·`scale` 은 큰 글 굵기·자간·크기. 굵기가 400 이하면 큰 숫자도 가늘게. `shape.radius` 는 창·카드 모서리.
- `scenes.frame` 이 `browser` 면 16:9·1:1 창 위 막대에 탭 대신 주소창(sub)이 들어가고 kicker 는 입력창 위 배지가 돼요.

## 글
- 사람이 말하듯 담백하게, 브랜드 말투(해요체 등)를 따라요. "~가 아닙니다, ~입니다" 같은 대조 구문은 쓰지 않아요.
- `kicker`: 창 위 탭 글. 14자 안쪽. 비우면 탭에 로고 글자가 들어가요.
- `title`: 입력창에 쳐지는 첫 문장. 24자 안쪽, `\n` 으로 두세 줄. 사용자가 앱에 실제로 쓸 법한 말이면 더 자연스러워요.
- `highlight`: title 안에 그대로 있는 낱말(띄어쓰기 단위).
- `points`: 결과 목록으로 하나씩 체크될 장점·기능 2~5개, 하나에 18자 안쪽(길면 두 줄로 작아져요).
- `number`: `{prefix, value, suffix, label, source}`. value 를 비우면 대시보드가 빠져요. 소수(4.8)도 돼요. label 은 카드 위, source 는 카드 아래 작은 글.
- `photos`: 0~4장. 앱 안 갤러리에 펼쳐져요. 미리보기에서는 비어 있는 사진 칸이 점선 자리로 보이고, 렌더할 때 사진이 하나도 없으면 갤러리 장면이 빠져요.
- `cta`: `headline`(두 줄 안쪽), `button`(버튼 글, 짧게), `sub`(사이트·계정. 토스트와 마지막 로고 아래에 나와요).
- `note`: 마지막 화면 맨 아래 작은 글 (가상 브랜드 표시, 기준일 같은 것).

### 화면 속 기능과 숫자는 실제 그대로
이 영상은 "앱에서 이렇게 된다"는 시연이라, 목록 항목과 숫자가 곧 제품 약속으로 읽혀요.
- points 에는 지금 실제로 되는 기능만 써요. 준비 중인 기능이면 "곧" 같은 말을 붙이거나 빼요.
- 숫자는 근거가 있는 것만, source 에 기준(대상·기간·비교 방법)을 적어요. 대시보드 그래프 선은 장식이라 값이 없지만, 숫자와 같이 보이니 숫자 자체가 사실이어야 해요.
- 버튼 문구의 "무료"는 조건(기간·대상·횟수)이 있으면 sub 나 note 에 같이 적어요.
- 가상 브랜드 예시에는 note 에 "템플릿 예시용 가상 서비스입니다" 같은 표시를 남겨요.

## 음악 (구글 Gemini)
- 깔끔하고 경쾌한 테크 런칭 곡, 뜯는 신스와 키보드 소리 같은 잔 타악, 따뜻한 베이스, 120BPM
- 0–2.5초는 타자 소리처럼 가벼운 틱만, 항목이 체크될 때마다 작은 밝은 강세, 대시보드·갤러리는 고른 그루브, 버튼을 누를 때 살짝 들리며 따뜻하게 마무리

## 확인할 것
- 화면에 나오는 기능(목록 항목)이 실제로 있는지
- 숫자의 출처와 기준 시점 (source 줄이 대시보드 카드 아래에 작게 나와요)
- 버튼 문구의 "무료" 같은 말에 조건이 있는지
- 사진에 고객 정보·개인정보가 보이지 않는지, 실제 그 가게·제품 사진이 아니면 note 에 "참고 사진"
- 9:16 에서 title 이 세 줄을 넘겨 너무 작아지지 않았는지 (그러면 줄을 더 짧게 나눠요)

## 더 나아가려면
- 실제 앱 스크린샷이 있으면 갤러리 대신 결과 화면 한 장이 카드 안에서 위로 스크롤되는 장면
- 협업 서비스라면 두 번째 사람 커서(이름표 단 다른 색)가 항목 하나에 댓글 말풍선을 다는 장면
- 마지막에 창이 작아지며 1:1·4:5·9:16 결과물 카드 여러 장이 옆으로 밀려 들어오는 장면
